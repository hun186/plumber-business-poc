# 水電好管家｜工程業務管理 PoC v0.4

繁體中文、適合個人師傅與小型承攬商的業務管理網站。**本版支援 SQLite 後端、成本紀錄、各類工程毛利分析與多工作表 Excel 匯出**，同時保留不需要帳號的虛構資料示範模式。

## 功能

- 客戶、工程案件、估價單（工項、數量、單價及 5% 營業稅）、收款登錄。
- **工程成本登錄**：材料、人工、外包、設備、其他，按工程歸戶，可編輯。
- **毛利分析**：依工程開始日期、業務類別與案件狀態篩選，計算案件金額、已登錄成本、估算毛利、估算毛利率、收款金額；支援類別分布、成本結構與個案分析。
- **Excel `.xlsx`**：可勾選客戶、案件、估價單、估價工項、收款、成本、業務類別毛利、成本類別統計、個案毛利與營運摘要；一份檔案多張工作表，篩選列、凍結標題、數字欄位。
- 手機與桌面 RWD；資料庫模式啟用登入驗證，同源檢查、HttpOnly Session Cookie。

## 對毛利計算的必要說明

- **案件金額**是 `projects.amount`，可能是「合約金額」或「預估報價」，不是已認列營收。
- **估算毛利 = 案件金額 − 該案已登錄成本**；估算毛利率 = 估算毛利 / 案件金額（案件金額為零時顯示不適用）。
- 收款金額是現金流，不是毛利，也不能直接當作收入。
- 尚未動工、進行中的案件通常尚未登齊成本，不能把高毛利當成真實獲利。已取消案件不納入毛利統計。
- 篩選日期以**工程開始日期**為準；一旦案件入選，成本與收款使用該案**全期間**登錄紀錄，不截斷成本以免低估；報表摘要含說明。
- 本階段為管理估算，尚未具備成本完整性驗證、開發票與稅額會計處理、履約進度營收認列及正式的損益表。

## SQLite：本機或固定主機部署

Node.js **22.13+**，不需要 PostgreSQL、Docker 或額外 npm 套件。

```bash
# 安全首次部署：由工具自動產生 .env 與 SQLite，不要手動複製範例作正式資料庫
node tools/owner-cli.js start
# 已有資料庫及 .env 的後續啟動，可使用 npm start
# 在同一台主機打開 http://127.0.0.1:3000
```

`.env`：

```ini
SQLITE_PATH=./data/plumber.sqlite
APP_ADMIN_PASSWORD=<自行設定高強度密碼>
AUTH_SECRET=<至少32個隨機字元>
```

- `.env` **不可**提交 GitHub；只有全新部署且本次執行剛自動建立 `.env` 時才允許第一次建立 SQLite。若既有 `.env` 卻遺失資料庫、或資料庫為空檔，所有啟動／檢查／備份必須報 `E_DB`，不得產生空白替代資料庫。既有資料請從已驗證的備份還原。`data/`、`*.sqlite`、`*.sqlite-wal` 已列入 `.gitignore`。
- 為避免未加密傳輸管理密碼，本機伺服器只綁定 `127.0.0.1`；若部署給其他人，必須另外由 HTTPS 反向代理接入，設置存取控制、備份及還原策略。
- 修改 SQLite 資料表請採版本化遷移；本版本已移除舊 PostgreSQL 建表腳本，僅使用 `db/schema.sqlite.sql`。

## Vercel 公開展示模式的重要限制

**Vercel 不能持久保存一般 SQLite 檔案。** Serverless Functions 的寫入空間為暫存，會隨實例替換而消失。系統在 `VERCEL` 環境下固定只使用**瀏覽器 localStorage 示範模式**，即使有設定 `SQLITE_PATH` 也不會聲稱啟用 SQLite。請勿輸入任何真實客戶個資。

若希望正式站使用真正持久的 SQLite，可改用**固定主機 / VPS / NAS** 執行 `npm start` 搭配 HTTPS 反向代理。或另行規劃遠端相容 SQLite 的服務，需另寫遠端資料介面；**不是**直接把 `.sqlite` 檔放在 Vercel 就可以。

## 驗證

```bash
npm run check
```

測試涵蓋 SQLite 建表／交易／外鍵、登入與同源防護、毛利及篩選計算、多工作表 XLSX 格式基礎檢查、Vercel 不啟用 SQLite。

## 後續規劃

1. 成本預算和實際成本分離、工時/材料採購來源、成本是否登錄完成標記。
2. 報價版本／轉正式訂單、變更追加減、應收帳款帳齡。
3. 多員工與角色權限、操作稽核、異地備份與 Windows 實機還原演練（站內 SQLite 手動／自動備份已提供）。

## v0.3 耗材與工程用料管理

- 耗材主檔：料號、名稱、單位、單位參考成本、庫存告警值。現存數量由不可隨意覆寫的庫存異動帳本計算。
- 倉儲作業：進貨入庫、工程領料、盤點調整。庫存扣除採 SQLite 即時交易，禁止負庫存及異動編號重複；變更品項參考單位成本不會追溯改寫已領料的成本。
- 工程備料：每工程／耗材預計需求數量、已領用、待領用及備料缺口；規劃不扣庫，領料才扣庫。領料會依領料當時的單位成本自動計入工程材料成本及毛利。
- Excel 增加「耗材庫存清冊」「工程材料需求」「庫存異動紀錄」。全庫清冊不受工程篩選影響；需求和工程領料跟著工程條件篩選。
- 資料庫升級：原有 SQLite 啟動時會安全建立 db/inventory.sql 內的新表，並保留既有客戶／工程／收款等資料；正式升級前請備份 SQLite（含 WAL）。
- Vercel 維持虛構範例瀏覽器模式，正式庫存必須部署於固定主機 SQLite。低庫存是**登入網站的畫面提醒**，不是背景 Email / 簡訊。
- v0.3 未提供多倉庫、採購單、退料／沖回、移動平均及 FIFO 成本核算。工程領料自動歸戶後，避免再手動重複登記同一筆材料成本。

## v0.4 多層工項／包項、材料配方與導覽

- 在「報價與工項 → 工項／包項範本」建立多層 **包項 → 子包項 → 可計價工項**，各工項可配置多種已建檔耗材和單位用量。
- 母包項不另外計價；套用至估價單時展開子工項，數量以各層預設數量相乘，金額由子工項單價計算。**既有估價單使用獨立快照**，修改範本不追溯改寫舊報價。
- 當報價狀態為「已接受」，可在估價列表明確點擊「同步工程備料」。系統依報價明細的材料快照產生報價來源需求；同工程同耗材已有**手動需求者優先保留**，不重複計算。欲調整報價需求可點「改為手動」。
- 同一工程若有多張已接受報價，以最後明確同步的報價來源需求為準，不能自動將所有報價加總。同步備料不扣庫存；只有實際領料才扣庫、計入工程成本。
- Excel 新增工項範本、工項材料配方工作表，材料數量使用最多三位小數格式。
- 左側導覽改為四個可收合群組，導航本身可捲動（含小螢幕），展開狀態保留在瀏覽器。
- SQLite 升級以 `db/catalog.sql` 增量建立資料表，舊工程、估價單與材料領料保持不變；正式環境更新前仍須備份。
- 目前包項以階層樹儲存：同一個工項範本不能同時掛在兩個母包項，若要跨包項共用需要後續實作多對多組合關係；目前可複製相同工項設定或單獨選用該工項。
- 公開 Vercel 站仍是 localStorage 虛構資料示範，非持久化倉庫。

## 業主免技術部署（Windows 單機）

**業主快速操作：**下載包含本節檔案的完整 ZIP 到本機（不要放同步資料夾），安裝 Node.js v24 LTS（最低 v22.13），再依序：

1. 雙擊 `啟動水電好管家.bat`：第一次自動建立安全設定與 SQLite，顯示管理密碼，開啟 http://127.0.0.1:3000
2. 雙擊 `部署檢查.bat`：檢查 Node.js、.env、SQLite 完整性。
3. 雙擊 `備份資料.bat`：以 SQLite `VACUUM INTO` 建立經 `quick_check` 驗證的 `backups/*.sqlite` 一致性備份。

完整手冊提供兩種版本：[GitHub 線上閱讀（Markdown）](docs/業主部署操作手冊.md)及[下載列印（Word）](docs/水電好管家_業主部署與故障排除操作手冊_v0.4.docx)。`data/`、`backups/`、`.env` 都不應上傳 GitHub 或交給無權限人員。安裝助手僅供**本機單機使用**，不支援把 3000 埠直接暴露至公網。

如出現 `E_NODE`、`E_ENV`、`E_CONFIG`、`E_PATH`、`E_DB`、`E_PORT` 或 `E_BACKUP`，依手冊 SOP 處理，勿自行刪除資料庫及 `-wal`／`-shm`。首次安裝必須以實際 Windows 電腦執行交付驗收，並在隔離環境演練還原。

**資料保護補充：**業主部署版本限制 SQLite 路徑只能是專案的 `data/*.sqlite`，拒絕絕對路徑、`..` 跳出及 UNC 網路分享；避免錯誤批次變更其他資料夾的 Windows 權限。Windows NTFS 私密資料以 PowerShell 建立僅當前 SID、SYSTEM、Administrators 的受保護 ACL，無法設定時拒絕啟動。`npm start` 直接啟動亦需通過相同權限檢查。

## 自動備份與歷史管理

正式單機 SQLite 模式提供「**系統管理 → 備份管理**」頁面，可設定**每隔幾天自動備份**（預設 1 天，1–365 天）及**最多保留幾份自動備份**（預設 50，1–500 份）；也能直接建立手動備份、查看歷史、下載副本及確認後刪除指定備份。

- 設定儲存在 SQLite 的 `backup_settings` 資料表，重開系統後仍保留。
- 只要本機服務正在執行，排程每分鐘檢查是否到期；若程式關閉、電腦關機，不會在那段期間執行。下次服務啟動時，如已過期會補做**一次自動備份檢查**（不逐天補做）；僅業務資料有變更、缺少有效自動備份或無法可靠比對時才建立新備份檔。
- 排程到期時先比較正式 SQLite 與最新一份可驗證的**自動備份**：針對業務資料表內容、結構與資料庫版本進行一致性摘要比對，忽略 `backup_settings` 排程狀態與 SQLite WAL／頁面布局差異。**內容相同則略過，不新增檔案、不消耗保留名額，並更新「上次自動檢查」供下次排程計算；內容不同則進行備份。**
- 沒有可用自動備份、既有備份遺失或損毀／無法可靠比對時，預設建立新備份而不是略過；僅手動備份存在也不取代第一次自動備份。手動備份始終依要求建立。
- 實際建立備份時以 SQLite `VACUUM INTO` 建立一致性快照，檢查 quick_check、外鍵與主要資料表筆數；錯誤會顯示於網頁。
- **保留份數只會清理較舊的自動備份。手動備份不受排程刪除**，但可在網頁個別刪除。
- 下載副本是備份，不等於線上還原。還原必須先停機，先確認備份並經管理人員在隔離環境處理。
- `backups/` 在同一硬碟上不能防範硬碟故障、遺失或勒索軟體；重要備份仍需定期複製到不同的受保護儲存裝置。Vercel 公開展示模式沒有這些備份功能。

**舊版 SQLite 升級安全規則：**新版本將 `PRAGMA user_version=5` 寫入資料庫作為版本標記。已標記的資料庫若整組工項或倉儲表消失，立即拒絕補建空表。沒有版本標記、但缺少新增式資料表的舊 v0.2/v0.3 資料庫，須由交付人員先保存與驗證離線備份，然後於單次升級程序明確設定 `OWNER_ALLOW_LEGACY_UPGRADE=1`；升級後應移除該設定，**不可直接要求非資訊背景業主操作**。

**SQLite 備份還原的 WAL 安全規則：** 必須停止所有網站及備份程序，先將正式 `data/plumber.sqlite`、存在的 `data/plumber.sqlite-wal`、`data/plumber.sqlite-shm` **整組封存**到隔離儲存位置，再整組移出正式 `data/`。正式路徑旁沒有任何舊 WAL/SHM 後，才複製驗證成功的備份作為 `data/plumber.sqlite`，執行部署檢查。**不能只覆寫 .sqlite 而留下舊 WAL/SHM。** 詳見 [還原 SOP](docs/業主部署操作手冊.md)。

**中斷備份暫存清理：** 完成且已驗證的 `.sqlite` 不受清理影響；程式在排程啟動或再次備份前保守回收已過期且沒有存活備份程序的 `.partial`／`.lock`，舊式無 PID 鎖定檔採更長安全等待期，不碰非本系統的檔案。
