# 水電好管家｜業主部署與故障排除操作手冊

適用：v0.4 業主部署整備版／Windows 單機／2026-10-22

> 此流程只適用包含「啟動水電好管家.bat」「部署檢查.bat」「備份資料.bat」的完整新版程式。舊版 main v0.4 沒有這三個按鈕式工具。公開 Vercel 展示站不是正式資料庫，請勿輸入真實客戶資料。

## 一、第一次安裝六步驟

1. 從交付者取得完整程式 ZIP 並解壓縮至本機資料夾，例如 C:\水電好管家。不要放在 OneDrive、網路共享或唯讀資料夾。
2. 從 https://nodejs.org/en/download 安裝 Node.js LTS，建議 v24、最低 v22.13。安裝完關閉並重開舊視窗。
3. 雙擊 **啟動水電好管家.bat**。首次執行會自動建立 .env、隨機管理密碼及 SQLite。
4. 把畫面第一次顯示的管理密碼抄錄到密碼管理器，勿外傳 .env 或密碼截圖。
5. 在同一台電腦開 http://127.0.0.1:3000。必須顯示「SQLite 資料庫」，不是「示範模式」。首頁應顯示總覽。
6. 新增一筆明確標記的測試客戶和測試工程，關閉瀏覽器再開確認資料仍在，然後雙擊 **備份資料.bat**，確認 backups 資料夾有 .sqlite 備份及 quick_check 通過訊息。

Node.js 是唯一事先要安裝的執行環境。不需要 Docker、SQL Server、MySQL 或 npm install。

## 二、每天使用

1. 雙擊 **啟動水電好管家.bat**，開啟本機網址登入。
2. 完成操作後先儲存，再關閉瀏覽器與啟動視窗。**關閉啟動視窗後，網站停止服務，資料仍在本機硬碟。**
3. 有重要異動的工作日，結束前雙擊 **備份資料.bat**，成功後另複製一份到安全的外接硬碟。

業務流程：客戶 → 工程 → 工項／包項範本 → 估價單 → 已接受估價單同步備料 → 實際領料 → 收款／成本／報表。規劃備料不扣庫；真正領料才扣庫。

## 三、真正的資料放在哪？

- .env：管理密碼及系統密鑰。**禁止上傳 GitHub、傳訊息或分享給無權限人員。**
- data/plumber.sqlite：客戶、報價、庫存等真正的資料庫。
- data/plumber.sqlite-wal、-shm：SQLite 運作檔，**不能手動刪除**。
- backups/plumber-backup-日期.sqlite：備份工具以 SQLite VACUUM INTO 建立的一致性資料庫副本。
- Excel 匯出僅是業務報表，不是系統資料庫備份。

## 四、故障排除 SOP

先抄下 **錯誤代碼、發生時間、當時操作**，再雙擊 **部署檢查.bat**。若涉及資料損毀，先停止所有操作並保留 data 與 backups。

| 代碼／症狀 | 可能原因 | 業主先做什麼 |
|---|---|---|
| E_NODE | Node.js 未安裝或過舊 | 安裝官方 LTS，重開視窗 |
| E_ENV | 找不到 .env | 初次執行請雙擊啟動批次檔；已使用過的資料先聯繫交付者 |
| E_CONFIG | 密碼、密鑰或埠不合要求 | 只提供錯誤代碼，**不要傳 .env** |
| E_PATH | 磁碟或資料夾沒有讀寫權限 | 檢查本機儲存位置與剩餘空間；有真實資料先備份 |
| E_DB | SQLite 遺失、空白檔、無法開啟、損毀或關聯檢查失敗 | **立即停止操作，不要重裝或建立新資料庫；保留 data/backups，聯繫交付者協助還原** |
| E_PORT | 服務已開啟或埠被占用 | 先試開本機網址；勿開兩份系統 |
| E_BACKUP | 備份失敗或備份完整性未通過 | 檢查空間與權限；備份成功前**不要升級** |
| E_API_JSON / E_API_SIZE | 傳送資料格式／大小異常 | 重新整理，減少單次輸入 |
| E_API_INTERNAL | 伺服器內部操作失敗 | 停止反覆點擊儲存，記時間與操作步驟 |
| 網頁打不開 | 啟動視窗已關或網址錯誤 | 看有無「啟動成功」，再輸入 127.0.0.1:3000 |
| 首頁空白／舊版本 | 瀏覽器快取 | Ctrl+F5；再執行部署檢查 |
| 登入失敗／示範模式 | 密碼、Cookie 或設定問題 | 用本機網址登入；示範模式不要輸入正式資料 |
| Windows 不明發行者 | ZIP／批次檔未簽章 | 先確認交付來源，**不要關掉防毒軟體硬闖** |

回報格式：公司／聯絡人、日期時間、Windows 版本、當時操作、錯誤代碼、部署檢查結果、最新備份日期，以及**已遮蔽個資和密碼**的截圖。未獲授權不要傳送 .env 或客戶資料庫。

## 五、備份、還原與換電腦

**備份：** 至少在有異動的每個工作日、重要庫存或報價修改後、升級前執行。雙擊備份資料，看到「完成」及「SQLite quick_check 正常」才算成功；再另外保存到**不同的實體裝置**。不要把使用中的 .sqlite、-wal、-shm 直接拖拉複製當成可靠備份。

**還原（建議由交付者處理）：** 先關閉網站停止操作；封存完整 data、.env、backups；在隔離資料夾先驗證要還原的 .sqlite 備份及資料筆數；取得業主同意還原時間點後，才替換正式資料庫。還原會使備份日後新增的資料消失，不可自行刪除 WAL。

**升級：** 停止網站 → 執行備份 → 複製整份舊專案作回復點 → 更新程式碼但**保留 .env、data、backups** → 執行部署檢查 → 啟動並核對資料。換電腦時請交付者安全移轉，不可同時讓兩台電腦各自修改不同的正式資料庫。

## 六、正式上線的界線

本版是單機 SQLite、只有同一電腦可開啟的 http://127.0.0.1 網址，且只有一組管理密碼。沒有內建多人帳號、角色控管、自動異地備份、遠端手機連線或開機自動常駐。**不能只開防火牆或轉送 3000 埠就提供遠端登入**；需要另外建 HTTPS、存取控制、備份及維運。毛利為管理估算，非正式會計或稅務報表。

## 七、交付簽收檢查

- [ ] Windows 已安裝相容 Node.js，雙擊啟動成功。
- [ ] 已保存管理密碼，登入顯示 SQLite 模式。
- [ ] 新增測試客戶及工程，重開網站後資料仍在。
- [ ] 工項套裝、材料配方、估價單及預覽可正常使用。
- [ ] 實際領料扣庫，純備料不扣庫；Excel 可匯出。
- [ ] 備份成功，另有外部第二份備份。
- [ ] 交付者在隔離環境驗證過還原。
- [ ] 業主知道 E_DB／資料遺失時要停用系統並通報。

交付記錄：安裝主機、程式版本與 Git Commit、安裝日期、備份日期、還原演練結果、業主驗收人與支援聯絡方式。

> 注意：自動化程式測試通過，不等同已在業主自己的 Windows 電腦完成實機驗收。交付者仍應確認現場安裝、備份與還原演練。
**Windows 特殊注意：**請固定將 SQLite 放在安裝目錄下的 `data` 子資料夾（例如 `data/plumber.sqlite`）；新版不允許把 SQLite 指向 C:\、其他文件資料夾或 UNC 網路磁碟，以免誤修改其他資料的權限。程式會以 Windows PowerShell 設定私密資料夾存取權限；權限檢查不通過將停止啟動，請提供 E_PATH 代碼給交付者。

**資料庫遺失防護：**第一次安裝須讓「啟動水電好管家.bat」自動建立管理設定及資料庫。若已經有 `.env`，但 `data/plumber.sqlite` 不見、或檔案為 0 位元組，部署檢查、啟動與備份會停止並顯示 `E_DB`，**不會建立新的空白資料庫，也不會用空白資料庫覆蓋舊備份**。請保留原始資料夾與備份，交由交付者在隔離環境確認可還原後處理。
